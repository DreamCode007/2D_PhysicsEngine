# PhysicsEngine

A C++ physics engine/game project built with **raylib**, **CMake**, **Ninja**, and **GCC (MinGW-w64)** on Windows 11.

The project includes raylib directly inside the repository, so **raylib does not need to be installed separately**.

# Overview

This project uses CMake to build both:

1. The PhysicsEngine application
2. The raylib library

Raylib is stored directly inside:

```text
external/raylib/
```

Therefore, the project does **not** depend on a separately installed raylib package.

The basic build process is:

```text
C++ Source Code
       |
       v
    CMake
       |
       +----------------+
       |                |
       v                v
    raylib         PhysicsEngine
       |                |
       +-------+--------+
               |
               v
       PhysicsEngine.exe
```

## Important directories

### `src/`

Contains the project's C++ source code.

Example:

```text
src/
├── main.cpp
```

Contains project resources such as:

```text
assets/
├── textures/
```

Contains the raylib source code.

It should **not** be committed to Git.

Example:

```text
build/

├── ...
```

# Prerequisites

A Windows 11 development machine needs:

- Git
- MSYS2
- GCC / MinGW-w64
- Ninja
- CMake

Raylib itself does **not** need to be installed separately.

---

# 1. Install MSYS2

Download MSYS2 from:

https://www.msys2.org/

Install it using the default location:

```text
C:\msys64
```

After installation, open:

```text
MSYS2 UCRT64
```

Do not use the regular MSYS2 terminal for building this project.

Use:

```text
MSYS2 UCRT64
```

because this project uses the UCRT64 GCC toolchain.

---

# 2. Install GCC

Open the **MSYS2 UCRT64** terminal.

Update the package database:

```bash
pacman -Syu
```

If MSYS2 asks you to close the terminal, close it.

Open **MSYS2 UCRT64** again and run:

```bash
pacman -Syu
```

Then install the UCRT64 GCC compiler:

```bash
pacman -S mingw-w64-ucrt-x86_64-gcc
```

Verify:

```bash
g++ --version
```

You should see output similar to:

```text
g++.exe (...) 15.x.x
```

---

# 3. Install Ninja

Install Ninja:

```bash
pacman -S mingw-w64-ucrt-x86_64-ninja
```

Verify:

```bash
ninja --version
```

---

# 4. Install CMake

CMake can be installed using the official Windows installer.

Download it from:

https://cmake.org/download/

Install the Windows x64 version.

During installation, enable:

```text
Add CMake to the system PATH
```

After installation, close and reopen your terminal.

Verify:

```bash
cmake --version
```

You should see something similar to:

```text
cmake version 4.x.x
```

Also verify the tools:

```bash
which g++
which ninja
which cmake
```

Expected output should look approximately like:

```text
/ucrt64/bin/g++
/ucrt64/bin/ninja
/c/Program Files/CMake/bin/cmake
```

The exact CMake path may differ depending on your installation.

# 8. Recompile After Changing Code

You do **not** need to delete the `build` directory after every change.

For example:

```text
src/main.cpp
```

is modified.

Save the file, then run:

```bash
cmake --build build
```

Ninja performs an **incremental build**.

Only files affected by the change are recompiled.

The typical development cycle is:

```text
Edit code
    ↓
Save
    ↓
cmake --build build
    ↓
Run PhysicsEngine.exe
    ↓
Edit code again
    ↓
...
```

For convenience:

```powershell
.\build.bat
```

can also be used.

However, during normal development:

```bash
cmake --build build
```

is faster because the CMake configuration already exists.

---

# 9. Clean Build

Sometimes you may want to completely rebuild the project.

Delete the build directory:

### MSYS2

```bash
rm -rf build
```

### PowerShell

```powershell
Remove-Item -Recurse -Force build
```

Then configure again:

```bash
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
```

and build:

```bash
cmake --build build
```

A clean build is useful when:

- CMake configuration becomes corrupted
- You change major CMake settings
- You change compiler/toolchain configuration
- You encounter strange linker/build errors

Do **not** perform a clean build after every source-code change.

# 10. CMake Configuration

The root `CMakeLists.txt` is responsible for building the project.

Current configuration:

```cmake
cmake_minimum_required(VERSION 3.20)

project(PhysicsEngine LANGUAGES C CXX)

set(CMAKE_C_STANDARD 11)
set(CMAKE_C_STANDARD_REQUIRED ON)

set(CMAKE_CXX_STANDARD 17)
set(CMAKE_CXX_STANDARD_REQUIRED ON)

if(NOT CMAKE_BUILD_TYPE)
    set(CMAKE_BUILD_TYPE Release CACHE STRING "Build type" FORCE)
endif()

add_subdirectory(external/raylib)

add_executable(PhysicsEngine
    src/main.cpp
)

target_link_libraries(PhysicsEngine PRIVATE raylib)
```

## What `add_subdirectory` does

This:

```cmake
add_subdirectory(external/raylib)
```

tells CMake:

> Build the raylib source located inside this repository.

This is why raylib doesn't need to be installed globally.

## Linking raylib

This:

```cmake
target_link_libraries(PhysicsEngine PRIVATE raylib)
```

links the PhysicsEngine executable with raylib.

# 11. Raylib

Raylib is included in:

```text
external/raylib/
```

The repository therefore contains both:

```text
Your Code
```

and:

```text
raylib source
```

This is intentional.

## Why vendor raylib?

This approach provides several benefits.

### No separate raylib installation

A new developer does not have to install raylib manually.

### Reproducible builds

Everyone builds against the same raylib source version stored in the repository.

### Works without downloading raylib

After cloning the repository, raylib is already available.

### Easy sharing

The project can be moved to another machine without installing raylib separately.

# 12. Assets

Game/engine assets should be placed in:

```text
assets/
```

For example:

```text
assets/
├── textures/
│   ├── player.png
│   └── background.png
│
├── sounds/
│   └── explosion.wav
│
└── fonts/
    └── game.ttf
```

When loading assets from C++, be careful about the working directory.

For example:

```cpp
Texture2D texture = LoadTexture("assets/textures/player.png");
```

The program should normally be launched from the project root if using paths like this.

# 15. Troubleshooting

## CMake is not recognized

Error:

```text
'cmake' is not recognized as an internal or external command
```

Install CMake and add it to PATH.

Then restart the terminal.

Check:

```bash
cmake --version
```

---

## G++ is not recognized

Make sure you're using:

```text
MSYS2 UCRT64
```

and that GCC is installed:

```bash
pacman -S mingw-w64-ucrt-x86_64-gcc
```

Then:

```bash
g++ --version
```

---

## Ninja is not recognized

Install:

```bash
pacman -S mingw-w64-ucrt-x86_64-ninja
```

Then:

```bash
ninja --version
```

---

## CMake cannot find raylib

Make sure this directory exists:

```text
external/raylib/
```

It should contain:

```text
external/raylib/CMakeLists.txt
```

If it doesn't exist, the raylib source was not cloned/copied correctly.

---

## Build directory is causing problems

Delete it:

```bash
rm -rf build
```

Then configure again:

```bash
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
```

Build:

```bash
cmake --build build
```

---

## Linker errors

If you get linker errors involving raylib, OpenGL, Windows libraries, or MinGW libraries:

1. Make sure you're using the UCRT64 environment.
2. Check:

```bash
which g++
```

Expected:

```text
/ucrt64/bin/g++
```

3. Check:

```bash
which ninja
```

Expected:

```text
/ucrt64/bin/ninja
```

4. Delete `build/`.
5. Configure again.
6. Rebuild.
